# Design

## Context

`EditorWindow` хранит сцену и подаёт её в оба представления. `LightingModel.cs` уже содержит всё, что требуется для восстановления прямого расчёта.

## Goals / Non-Goals

- Переносить редактируемую сцену и фотометрию одним файлом.
- Сбрасывать выделение и производные результаты после успешного открытия. Результаты вычисляются повторно.

## Decisions

- Использовать UTF-8 JSON с расширением `.lighting.json` и обязательным целым полем `formatVersion` со значением 1. Контракт хранения описать отдельными DTO. Сохранять таблицы углов и кандел после применения множителя IES, чтобы восстановить расчёт без исходного файла.
- Валидировать размеры, координаты, конечность чисел, порядок углов и размерность фотометрических таблиц до изменения состояния окна. Проверять ограничения, общие с моделью и редактором. Пустой список светильников допустим.
- Для записи использовать временный файл в каталоге назначения и заменять целевой файл только после завершения записи. При сбое удалять временный файл по возможности. Успешную запись отмечать как сохранённую только для той ревизии, которая записана.
- Использовать платформенные диалоги Avalonia и отслеживать изменения сцены по ревизии. Сначала загрузить и проверить выбранный файл, затем разрешить несохранённые изменения и применить сцену. Сериализовать файловые действия и отменять устаревший расчёт при замене сцены.

## Risks / Trade-offs

- JSON с числовыми массивами увеличивает размер проекта. Проверка структуры и версии позволяет диагностировать повреждения и закладывает основу для миграций.
- Переносимость диалогов и замена существующего файла требуют ручной проверки на обеих целевых ОС.
